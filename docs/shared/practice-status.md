# 実習を始める前の確認

各章は、何を作り、測り、考えるかを説明する教材です。実機の型番、配線図、ビジュアルプログラミング環境、通信方式、ブラウザ実習アプリはまだ確定・実装されていません。掲載した学習手順は、以下の確認を済ませてから実施します。実機が用意できない段階では、予想、紙上の計算、記録方法の設計から学べます。

## 実機を使う前に

1. {ref}`hardware-specifications` に型番、電圧、電流、極性、使用ピン、メーカー資料を記録する。
2. 電源を切った状態で、確認済み配線図と実際の接続を照合する。モーター・サーボの電源をGPIOから供給しない。
3. 停止操作、異常時の電源切断、通信が途切れたときの停止を確認する。走行・アーム動作の範囲を確保する。
4. 車輪を浮かせるなど、移動しない状態で方向・信号・計測を確認してから、低い指令値で実験する。
5. 測定器の接続、レンジ、定格を確認する。故意の短絡、モーターの長時間拘束、定格超過を実験に使わない。

具体的な電池個数、抵抗値、GPIO番号、PWM周波数、制御係数は部品選定後に決めます。本文中の計算例の数値は、明記した説明用の仮定であり、実機にそのまま設定する値ではありません。

## プログラムとブラウザ実習

`text` のコード枠は処理の流れを示す疑似コードです。そのまま実行できるプログラムや、完成済みのアプリを示しません。実装時にはボード、ライブラリ、指令の範囲、単位、タイミングを確定し、サンプルコードと本文を対応させます。

ESP32はモーター・センサの処理を、PC・スマートフォンは画面・画像処理・AIを担当します。周期的なモーター制御をブラウザの通信到着時刻に依存させず、ESP32側で実行する構成を検討します。通信の遅延と切断も実験条件に含めます。

## 学習段階と実験記録

入門は観察と説明、基本は測定・計算、発展はモデル・数式・比較に取り組みます。発展課題の数学は入門の必須条件ではありません。第25〜28章には専門的な前提があるため、必要な知識を確認して選択します。

実験ノートには問い、予想、変更した条件、そろえた条件、装置、時刻と単位、観測・測定した結果、考察を残します。失敗した試行も消さず、失敗条件と修正内容を記録します。{ref}`notation-conventions` に従い、実測・理論・シミュレーション・説明用の仮定を区別します。

各章の確認問題の「考え方」は説明の例です。実験結果が一つに決まることを意味しません。測定結果には測定方法、ばらつき、モデルの適用範囲を添えます。
