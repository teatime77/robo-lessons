# 第22章　データから判断するAIを作ろう

## 問いと到達目標

人が条件を全部書かずに、例から分類を学べるでしょうか。画像・音・動作のいずれか一つを選び、データ収集、学習、独立した評価の流れを説明します。

## 前提知識と関連する章

{ref}`camera-target` の検出と評価、{ref}`text-programming` のデータ処理を使います。基本では割合とグラフ、発展では確率・微分を扱います。

## 必要な部品・工具

PCまたはスマートフォン、選んだ入力を記録する機器、分類対象、データ整理環境を使います。学習ツールと推論アプリは未選定です。クラウドや有料サービスを必須にせず、まずデータと評価方法を設計します。

## 学ぶこと

### 教師データとラベル

教師あり分類では、入力の例と正解の分類を組にします。ラベルの意味を先に決め、曖昧な例をどう扱うか記録します。同じ対象でも照明、角度、距離等を変え、実際に使う条件を含めます。

枚数だけでなく、例の種類と偏りが重要です。一つの分類だけ背景が違うと、目的物ではなく背景の特徴で当てる可能性があります。入力形式、収集条件、ラベル、作成者の確認を記録します。

### 学習・検証・評価を分ける

学習用データでモデルを調整し、検証用で設計を選び、最後に独立した評価用データで性能を確認します。近い時刻の動画フレームや同じ対象のほぼ同一画像を無作為に分けるだけでは、似た例が混入します。撮影日、個体、収集のまとまりで分ける方法を考えます。

学習に使った例では良くても、新しい例で失敗する場合を過学習の問題として扱います。[TensorFlow公式の過学習・未学習の解説](https://www.tensorflow.org/tutorials/keras/overfit_and_underfit)。

### モデルの出力と判断

分類モデルは各分類のスコア等を出します。最大のスコアが高くても、未知の対象に正しく対応できる保証ではありません。「判断を保留する」「人へ確認を求める」「停止する」条件を追加します。

発展では、予測と正解の違いを測る損失関数と、それを減らすパラメータ更新を学びます。分類の例として正解クラスの予測値 $p_y$ に対する $-\log p_y$ を考え、正解へ小さい値を出すほど損失が大きくなることを調べます。微分や誤差逆伝播は発展の前提を整えて扱います。

## 予想

背景だけが変わった画像や、どの分類にも入らない物を見せると、モデルはどう判断するでしょうか。

## 工作・配線・プログラミング

1. 分類したい対象と、失敗をどう判定するかを決めます。
2. 収集条件を分けてデータを集め、ラベルを確認します。
3. 学習・検証・評価用を、同じ例が混ざらない単位で分けます。
4. 採用した環境で学習し、学習条件とモデル版を保存します。
5. 評価結果を見て失敗条件を分析し、追加収集や設計の変更を行います。評価用データを繰り返し設計に使ったら、その独立性を見直します。

## 実験と計測

各分類の件数、正しく分類した数、他の分類へ間違えた数、保留、推論時間を記録します。混同行列で「何を何と間違えたか」を示します。全体正解率だけでなく、分類ごとの違いを見ます。

## 結果の整理と考察

単純な手書きルールも同じ評価条件で比べます。学習モデルが常に優れるとは決めず、必要なデータ、処理時間、説明のしやすさを考えます。新しい条件での成功は、その条件で評価した範囲の結果です。

## 課題

- **入門**：例と正解のラベルを整理し、分類を実演する。
- **基本**：独立した評価で混同行列を作り、失敗条件を説明する。
- **発展**：データ分割やモデルの複雑さを変え、損失・評価性能・過学習を比較する。

**確認問題**：同じ画像を学習と評価の両方に使えば、実際の性能をよく評価できますか。**考え方**：既に見た例を覚えている可能性があり、新しい条件での性能を判断できません。

## トラブル対処

| 症状 | 確認と対処 |
| --- | --- |
| 学習は良いが評価は悪い | データ混入、偏り、条件差、過学習を確認 |
| 一つの分類へ偏る | 件数、ラベル誤り、入力の前処理を確認 |
| 動作中だけ失敗する | ぼけ、撮影条件、入力更新、推論遅延を確認 |
