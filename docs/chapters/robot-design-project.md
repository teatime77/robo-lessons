# 第24章　自分のロボットを企画し、改良しよう

## 問いと到達目標

学んだ部品とプログラムで、どんな問題を解決できるでしょうか。目的、仕様、製作、評価、改良、発表を一つのプロジェクトとして進め、他の人が再現できる資料を作ります。

## 前提知識と関連する章

選ぶテーマに必要な章を復習します。運搬なら {ref}`cargo-transport`、アームなら {ref}`planar-arm`、人への反応なら {ref}`communication-robot` が中心です。全機能を必ず使う必要はありません。

## 必要な部品・工具

課題に必要な部品・工具・ソフトウェアを自分で一覧にします。既存部品を使えるか、定格や取付を変更する必要があるかを {ref}`hardware-specifications` と照合します。費用・時間・製作環境も制約として記録します。

## 学ぶこと

### 問題と仕様を分ける

「荷物を運ぶ」は目的ですが、何を、どこへ、どの条件で運ぶかはまだ曖昧です。対象物、距離、停止の許容範囲、所要時間、操作方法を、実際に確認できる条件で表します。仕様の数値は目標であり、達成済みの性能ではありません。

解決したい問題を観察してから、必要な機能を選びます。AIや多数のセンサを使うこと自体を目標にせず、単純な方法で目的を達成できるかも検討します。

### 分けて作り、合わせて確認する

機構、電源、計測、動作、表示を小さく分け、各部分の入力・出力・単位を決めます。個別に確認してから組み合わせると、不具合の位置を探しやすくなります。

共同作業では、担当者、変更内容、版、確認済み条件を記録します。配線や通信の変更は、相手側のコードと資料も同時に直します。見た目の完成と、仕様を満たしたことを別に評価します。

### 比較できる改良

改良前後を同じ条件で比べるため、先に評価方法を決めます。成功率、時間、誤差、消費エネルギー等から目的に合う指標を選びます。一度に多くの条件を変えず、どの変更が効いたかを追えるようにします。

## 予想

最も難しい条件、失敗しそうな部分、最初に確認すべき部品を挙げます。「この変更で何が良くなるか」を、改良前に書きます。

## 工作・配線・プログラミング

1. 問題、利用者、使用条件、成功の基準を1枚にまとめます。
2. 機能を分け、部品表、電源・配線、通信、状態、工程を設計します。
3. 最小限の動く試作を作り、{ref}`practice-readiness` に従って確認します。
4. 評価計画で測り、失敗の原因を絞って改良します。
5. 別の人が資料を見て再現し、説明不足や条件の抜けを確認します。

## 実験と計測

| 評価の設計 | 記録する内容 |
| --- | --- |
| 何を成功とするか | 条件と判定方法、許容範囲 |
| 何をそろえるか | 装置、床、電源、対象、開始位置 |
| 何を比べるか | 変更前後の版、指標、試行数 |
| どう失敗したか | 状態、時刻、症状、再現条件 |

## 結果の整理と考察

達成した仕様、未達の仕様、確認していない条件を分けて報告します。成功した動画だけでなく、繰り返しの結果と失敗例を示します。模型やシミュレーションのみで確認した部分を実機の性能とは呼びません。

共有する資料には、ソースコード、部品表、CAD編集元、配線図、実験記録、実行方法、版、出典を含めます。外部素材のライセンスも記録し、他の人が利用できる条件を確認します。

## 課題

- **入門**：目的を一つ決め、最小の試作を実演する。
- **基本**：仕様と評価表を作り、変更前後を同条件で比べる。
- **発展**：第三者による再現と異なる条件での評価を行い、限界を説明する。

**確認問題**：改良後だけ新しい電池を使って速くなった場合、機構の改良が効いたと言えますか。**考え方**：電源条件も変わっているため、原因を分けられません。条件をそろえる比較が必要です。

## トラブル対処

| 症状 | 確認と対処 |
| --- | --- |
| 機能が増えて進まない | 成功基準を見直し、最小試作へ絞る |
| 組み合わせると動かない | 版、単位、通信、電源、各部分の入出力を照合 |
| 結果を再現できない | 使用部品、条件、開始状態、変更履歴を補う |
