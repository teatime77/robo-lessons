# 第7章　障害物の前で止まろう

## 問いと到達目標

決まった時間だけ走る方法から、周囲を見て止まる方法へ進みます。障害物までの距離を読み、条件分岐で停止を判断し、停止指令を出してから止まるまでの移動を説明します。

## 前提知識と関連する章

{ref}`visual-vehicle-control` の停止操作と {ref}`travel-distance` の速さ・時間・距離を使います。比較記号と「もし〜なら」をブロックで表します。実機の確認は {ref}`practice-readiness` に従います。

## 必要な部品・工具

四輪車、距離センサ、取付具、柔らかい障害物、定規、記録機器を使います。センサ方式、電源・信号電圧、測定範囲、更新間隔は {ref}`hardware-specifications` で確認します。電圧変換が必要かを調べてからESP32へ接続します。

## 学ぶこと

### センサ値と有効な測定

距離センサは物理現象から距離を推定します。方式によって、材質、表面の向き、光、反射、測定範囲外の物体等が影響します。表示された数値をいつも正しい距離とみなさず、定規による距離と比較します。

測定不能、範囲外、古いデータを区別する必要があります。未取得値を0や「十分遠い」に置き換えると、危険な判断につながります。測定の有効性と時刻も扱い、判断できない場合の停止を先に決めます。

### しきい値と停止距離

距離 $d$ がしきい値 $d_{\mathrm{stop}}$ 以下なら停止する条件を作ります。センサの位置から車体前端までの距離も考えます。センサが障害物に接触するまでの距離と、車体が接触するまでの距離は同じとは限りません。

検出・処理・通信・制御には遅れがあり、停止指令後にも進みます。発展では、速さ $v$、遅れ $T$、一定の減速度の大きさ $b>0$ を仮定すると、停止に必要な距離を $vT+v^2/(2b)$ とモデル化できます。ただし実機の保証値ではなく、床や負荷を変えた計測で余裕を検討します。

## 予想

同じしきい値で速さだけを上げると、停止位置はどう変わるでしょうか。斜めの板や柔らかい物体を置いたときの測定も予想します。

## 工作・配線・プログラミング

1. センサを固定し、車体前端との位置関係を測ります。
2. 走らせずに、定規で測った距離とセンサ値を比べます。
3. 次の疑似コードをブロックで表します。

```text
繰り返す：
    距離と測定時刻を読む
    値が無効、古い、または停止条件を満たすなら停止
    それ以外なら低い指令で前進
```

4. 最初は十分に離れた位置から低い指令で試し、停止後は人の確認で再開する方式にします。
5. 範囲外・通信切断でも停止できることを確認します。

## 実験と計測

指令値、物体の材質・向き、センサの更新間隔を一つずつ変えます。センサ値、定規の距離、停止指令時刻、最終停止位置、検出失敗を記録します。停止後の最短すき間も測り、車体前端を基準にします。

## 結果の整理と考察

「見つけられたか」と「間に合って止まれたか」を分けます。同じしきい値でも停止位置が変わる理由を、測定誤差、遅れ、慣性、床の条件から考えます。成功した一回だけで十分とは判断しません。

## 課題

- **入門**：障害物を近づけ、条件分岐のどちらが実行されるか説明する。
- **基本**：材質・向きを変え、実距離とセンサ値の対応表を作る。
- **発展**：停止距離のモデルと実測を比べ、速さに応じたしきい値を検討する。

**確認問題**：距離の値が更新されなくなったとき、最後の値を使い続けてよいですか。**考え方**：車や障害物が動けば古い値は現在の状況を表しません。時刻を確認し、定めた期限を超えたら停止する処理が必要です。

## トラブル対処

| 症状 | 確認と対処 |
| --- | --- |
| 距離が飛ぶ・取得できない | 測定範囲、物体の向き、接続、更新状態を確認 |
| 障害物に近づきすぎる | 車体前端、処理遅れ、走行指令、しきい値を見直す |
| 止まった直後に再発進する | 停止を保持し、人が確認して再開する条件へ変更 |
