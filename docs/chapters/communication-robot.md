# 第23章　反応するコミュニケーションロボットを作ろう

## 問いと到達目標

人の合図に反応するとき、どの動きや表示なら意図が伝わるでしょうか。顔の表示、首振り、カメラ、必要に応じてマイクを組み合わせ、イベント・状態・反応時間を説明します。

## 前提知識と関連する章

{ref}`servo-gripper` の動作範囲、{ref}`camera-target` の検出、{ref}`data-driven-ai` の評価を使います。最初はボタン入力から始め、画像や音の分類は選択して追加できます。

## 必要な部品・工具

PCまたはスマートフォンの画面、確認済みサーボ機構、カメラ、必要に応じてマイクを使います。表示アプリと検出・通信は未実装です。撮影・録音する場合は対象者と範囲を確認し、評価に必要な記録を決めます。

## 学ぶこと

### イベントと状態

ボタンが押された、対象を見つけた、一定時間見失ったという出来事をイベントとして扱います。「待機」「相手を確認」「反応」「復帰」「停止」の状態を決めると、同じイベントへ何度も反応することを防ぎやすくなります。

イベントだけでなく、検出時刻、有効性、現在の状態を見て判断します。首振り中に同じ合図が来た場合、反応を追加するか無視するかを先に決めます。

### 表示と動きを合わせる

顔の表情、向き、音、動作の開始時刻がそろうと、反応の意味を伝えやすくなります。表示に「考え中」「確認できない」等の状態を示せば、処理が終わっていないことも伝えられます。表情だけから本当の感情や理解があるとは説明しません。

### 追従と滑らかさ

画像の対象位置から首の角度を変える場合、画像座標と機構角度の対応を確認します。検出位置のばらつきをそのまま角度へ入れると細かく動き続けるため、許容範囲、平滑化、角度の変化量制限を検討します。

平滑化は反応を遅くすることがあります。対象の移動を予測する発展課題でも、見失った対象を推定だけで追い続ける条件を制限します。サーボの可動限界と通信断時の処理は画像処理とは別に確認します。

## 予想

すぐ反応する場合と少し遅れて反応する場合、急に首を振る場合と段階的に動く場合で、相手はどう受け取るでしょうか。

## 工作・配線・プログラミング

1. 紙に状態と表情・動作・遷移条件を書きます。
2. ボタン入力だけで、待機から反応、復帰までの表示を試します。
3. 確認済み範囲で首の動きを加えます。{ref}`practice-readiness` に従います。
4. カメラ等の入力を加え、見失った場合は追従を止めます。
5. 反応を一度だけ出す条件、連続入力、停止操作を確認します。

## 実験と計測

入力時刻、判断時刻、表示・動作の開始、完了、状態の履歴を記録します。合図の種類、距離、照明、誤反応、見逃し、反応時間を比べます。参加者の「分かりやすい」等の回答は、機械的な計測値とは別に整理します。

## 結果の整理と考察

認識できた割合と、反応が理解された割合を分けます。合図なしで動く、同じ合図へ何度も動く、入力が古いまま動く等の問題を状態の記録から調べます。

## 課題

- **入門**：ボタンで表情を変え、各状態の意味を説明する。
- **基本**：検出に反応する動作を作り、誤反応と反応時間を記録する。
- **発展**：追従の平滑化や予測を比べ、遅れ・滑らかさ・見失いへの対処を評価する。

**確認問題**：一つの合図が10フレーム続いたら、10回首を振るべきですか。**考え方**：一回の合図に一回反応する設計なら、状態やイベントの立ち上がりを使って重複を防ぎます。

## トラブル対処

| 症状 | 確認と対処 |
| --- | --- |
| 首が細かく震える | 検出のばらつき、許容範囲、角度制限を確認 |
| 表情と動作がずれる | 状態と各処理の時刻、通信遅れを確認 |
| 見失っても動く | データ期限、無効状態、追従停止の条件を確認 |
