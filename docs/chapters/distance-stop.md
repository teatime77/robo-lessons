# 第11章　指定した距離で止まろう

## 問いと到達目標

毎回同じ時間だけ走る方法より、距離を読みながら止まる方法は正確でしょうか。目標と推定距離の差を求め、接近時の減速と停止条件を作り、独立した実測で評価します。

## 前提知識と関連する章

{ref}`wheel-encoder` の距離換算、{ref}`speed-measurement` の速度、{ref}`obstacle-stop` の判断を使います。目標・現在値・誤差という制御の言葉を導入します。

## 必要な部品・工具

エンコーダー付き四輪車、ESP32、床の距離目盛、停止目標のテープを使います。計測と停止の処理を実装する環境は選定後に確定します。実施条件は {ref}`practice-readiness` に従います。

## 学ぶこと

### 目標と誤差

一方向の直線走行で、目標距離を $d^*$、回転から推定した距離を $\hat d$ とし、残り距離を $e=d^*-\hat d$ と定義します。$e>0$ は未到達、$e<0$ は推定上の行き過ぎです。実測した車体位置とは区別します。

開ループでは結果を見ずに指令します。フィードバックでは測った結果を次の指令に反映します。距離を読んで止めるだけでも、その入口になります。

### 減速と終了判定

目標を超えた瞬間に停止指令を出しても、その後に進む場合があります。まず手前から低い指令へ切り替え、残り距離が小さくなったら停止します。低すぎる指令では動かないこともあるため、指令を下げれば必ず滑らかに止まるとは限りません。

「到達」は許容範囲と時間を使って定義します。停止後の自動後退を安易に加えると往復するため、最初は停止を保持して結果を記録します。計数停止や最大実行時間超過も終了条件に含めます。

## 予想

時間だけで止める方法と、距離で止める方法は、電源状態や軽い荷物が変わったときにどう違うでしょうか。

## 工作・配線・プログラミング

1. 開始位置を決め、左右カウントと推定距離を初期化します。
2. 目標、減速を始める残り距離、許容範囲を決めます。数値は実機で確認します。
3. 次の疑似コードを実装環境へ対応させます。

```text
計測を更新し、残り距離を求める
無効な計測・時間超過・障害物 → 停止して異常終了
停止範囲に到達 → 停止して結果を保存
減速範囲に入った → 低い指令へ切り替える
それ以外 → 前進
```

4. 低い指令の短い走行から始め、停止後の位置を目盛で測ります。
5. 同じ目標で時間のみの方法も試し、条件をそろえて比較します。

## 実験と計測

目標距離、減速開始条件、指令、最終カウント、推定距離、目盛による実距離、停止までの時間を記録します。車輪の換算誤差と停止制御の誤差を分けるため、目盛等の独立した測定が必要です。

## 結果の整理と考察

目標との差を推定値と実測値の両方で計算します。推定では目標に一致しても、実機が滑れば位置はずれます。平均の行き過ぎと試行間のばらつき、停止までの時間を一緒に比べます。

## 課題

- **入門**：残り距離が減る様子を見て、停止条件を説明する。
- **基本**：二つの停止方法の実距離とばらつきを比較する。
- **発展**：速度に応じた減速開始条件を設計し、荷物変更時の結果を調べる。

**確認問題**：エンコーダーの推定距離が目標と同じなら、車体も目標位置にいると言えますか。**考え方**：滑りや車輪径の誤差があるため保証できません。独立した位置の実測が必要です。

## トラブル対処

| 症状 | 確認と対処 |
| --- | --- |
| 到達しても止まらない | 比較条件、符号、初期化、計測更新を確認 |
| 手前で動かなくなる | 指令が動作可能な範囲か確認し、時間超過で停止 |
| 停止後に前後を繰り返す | 到達時の状態保持、許容範囲、再開条件を確認 |
