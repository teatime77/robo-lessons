# 第2章　ビジュアルプログラミングでモーターを動かそう

## 問いと到達目標

「回る、待つ、止まる」を、どのような順番の指示にすれば再現できるでしょうか。ブロックで回転・停止・逆回転を組み、実行順序とモータードライバーの役割を説明します。

## 前提知識と関連する章

{ref}`battery-motor-led` の閉じた回路と電源の確認を使います。数式や文字によるプログラミングは不要です。実施条件は {ref}`practice-readiness` に従います。

## 必要な部品・工具

DCモーター、ESP32搭載ボード、適合するモータードライバー、確認済み電源、PCまたはスマートフォン、モーターを固定する台を使います。ブロック環境、ボード型番、使用ピン、通信方法、指令の範囲は未確定です。

## 学ぶこと

### 指令と電力を分ける

マイコンはプログラムに従って信号を出し、ドライバーはその信号を受けてモーターへ電力を供給します。GPIOをモーターの電源として使いません。「入力→処理→出力」は、開始ボタンの入力、ブロックの処理、ドライバーへの出力として考えます。

### 順次実行と待ち時間

プログラムは決めた順に進みます。「回転」の次にすぐ「停止」を置くと、目で分かるほど回転しないことがあります。待ち時間は、次の指示へ進むまでの時間です。開始・終了・停止を明示すると、途中で何が起きたか追いやすくなります。

### PWMは速さそのものではない

PWMは一定周期の中で信号が有効になる割合を変える方法です。その割合をデューティ比と呼びます。モーターの回転速度は負荷、電源、摩擦などにも依存し、デューティ比を2倍にしても速度が2倍になるとは限りません。

ESP32ではLEDC等でPWMを生成できますが、周波数と分解能には設定上の関係があります。実装時は使用ボードとSDK版を確認します。[EspressifのLEDC公式資料](https://docs.espressif.com/projects/esp-idf/en/stable/esp32/api-reference/peripherals/ledc.html)。

## 予想

待ち時間を長くすると何が変わるか、指令を弱くすると必ず回転するかを予想します。方向を変える前に停止を入れる理由も考えます。

## 工作・配線・プログラミング

1. 電源を切ってドライバーとモーターを接続し、軸と配線を固定します。
2. ブロックの開始・停止操作、通信切断時の停止を先に確認します。
3. 次の流れを、採用した環境のブロックに対応させます。

```text
開始 → 正方向へ回転 → 決めた時間待つ → 停止
     → 停止を確認 → 逆方向へ回転 → 待つ → 停止 → 終了
```

4. 停止方法と方向切替条件をドライバー仕様に合わせ、低い指令から試します。
5. 待ち時間、方向、指令値を一度に一つだけ変えます。

上の流れは疑似コードです。停止には惰性停止・制動等の違いがあり、採用ドライバーの設定を確認します。

## 実験と計測

同じモーターと電源で、待ち時間だけを変えた試行と、指令値だけを変えた試行を分けます。指令、実行時間、方向、回り始めたかを記録します。速度を数値で主張する場合は回転量と時間を測り、見た印象と分けます。

## 結果の整理と考察

ブロックの順序と実際の動作を時系列で対応させます。小さい指令で回らない場合は、摩擦に打ち勝つ力が不足している可能性と、配線・設定の問題を切り分けます。

## 課題

- **入門**：正転と停止を作り、次に実行されるブロックを指で示す。
- **基本**：待ち時間を変えて動作を比較し、条件と結果を表にする。
- **発展**：指令と回転速度の関係を測り、単純な比例で説明できる範囲を調べる。

**確認問題**：「待つ」を削除すると、回転の指示も消えますか。**考え方**：回転指示は残りますが、すぐ停止へ進むため、回転が見えにくくなることがあります。プログラムの指示と目で見える結果を区別します。

## トラブル対処

| 症状 | 確認と対処 |
| --- | --- |
| 実行しても動かない | 電源を切り、ドライバー電源・使用ピン・指令範囲を確認 |
| 向きが予想と逆 | 正方向の定義と接続を確認し、電源を切って修正 |
| 停止操作が効かない | 電源を切り、停止信号・通信切断時の動作を修正してから再開 |
