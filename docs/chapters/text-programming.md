# 第15章　ブロックからテキストのプログラムへ進もう

## 問いと到達目標

これまでのブロックを文字で書くと、どのような構造になるでしょうか。慣れた動作を変数・条件分岐・繰り返し・関数で表し、表示と実機処理の役割を分けます。

## 前提知識と関連する章

{ref}`visual-vehicle-control` の繰り返し、{ref}`obstacle-stop` の条件分岐、{ref}`cargo-transport` の状態を使います。まず一つの言語を選び、全言語を同時に習得する必要はありません。

## 必要な部品・工具

PC、エディタ、選定した実行環境、既存のブロックプログラムを使います。実機との接続は {ref}`practice-readiness` と共通配線の確認後に行います。完成済み通信APIやサンプルアプリはまだありません。

## 学ぶこと

### 変数・関数・配列

変数は目標距離、測定値、現在の状態等へ名前を付ける仕組みです。名前だけでなく単位も定義します。`distance_m` と `distance_mm` のように単位を明示すれば、換算ミスを見つけやすくなります。

関数は「距離を計算する」「停止する」等のまとまりに名前を付けます。入力と出力を明示すると、測定値を与えて計算だけを確認できます。配列は時刻ごとの記録を順に保持する用途で使います。位置や速度の対応が崩れないよう、一つの記録としてまとめます。

### 言語と動く場所

ブラウザ側はTypeScriptを中心に考え、JavaScriptとの関係を学びます。TypeScriptの型は開発時の確認に役立ちますが、外から届いたデータの値や範囲を実行時に検証する処理は別に必要です。[TypeScript公式の入門資料](https://www.typescriptlang.org/docs/handbook/typescript-in-5-minutes.html)。

Pythonはデータ整理・数値計算の候補、C/C++はESP32の実装を読む候補です。使える言語やAPIは採用環境に依存します。ブラウザで書いた処理が、そのままESP32で実行されるとは限りません。

### 時間とデバッグ

文字で書いても、処理の順序を追う考え方は同じです。状態、指令、センサ値、時刻を記録すると、期待と違う段階を探せます。長い待ち処理で停止判断を妨げないよう、経過時刻による状態遷移も考えます。

## 予想

同じ名前の変数に違う単位の値を入れたら何が起きるか、停止関数を一か所で定義する利点は何かを考えます。

## 工作・配線・プログラミング

1. 既存ブロックの各部分を、変数・条件・繰り返し・関数へ対応させます。
2. 最初は実機出力を使わず、画面表示や記録だけで処理の順序を確認します。
3. 次の疑似コードを選定した言語に書き換えます。

```text
距離の記録を受け取る
形式、単位、時刻、範囲を確認する
異常なら停止状態へ移る
有効なら残り距離を計算し、状態に応じて指令を決める
判断の理由と結果を記録する
```

4. 計算へ説明用データを与え、境界値・無効値を確認します。
5. 実機APIの仕様を確定した後に、低い指令の動作で対応を比較します。

## 実験と計測

同じ動作について、ブロックとテキストの入力、条件、出力を表にします。単位違い、欠測、期限超過を与えたときの分岐も記録します。模擬入力の結果は実測とは呼びません。

## 結果の整理と考察

文法の誤り、条件の誤り、単位の誤り、実機接続の誤りを分けます。短く書くことだけを目標にせず、後から読んで指令と停止条件を追えるかを評価します。

## 課題

- **入門**：ブロックとテキストの対応を図にする。
- **基本**：距離換算を関数にし、入力・出力・単位を説明する。
- **発展**：時刻で状態を切り替え、停止判断を継続できる構造を作る。

**確認問題**：型を指定すれば、センサから来た負の時間間隔も防げますか。**考え方**：数値型であっても値の意味は検証が必要です。時間差が正であること等を実行時に確認します。

## トラブル対処

| 症状 | 確認と対処 |
| --- | --- |
| 条件が逆に動く | 比較演算、値の単位、符号を確認 |
| 操作画面が止まる | 長い待ち、繰り返し、表示更新と計算の役割を確認 |
| 計算だけ合うが実機が違う | API仕様、指令範囲、送信時刻、接続を照合 |
