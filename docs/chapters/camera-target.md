# 第21章　カメラで目標を見つけよう

## 問いと到達目標

画面に写った物を、ロボットの判断に使えるでしょうか。色や印の検出を試し、画像座標、検出の失敗、処理遅延を説明します。

## 前提知識と関連する章

{ref}`text-programming` のデータと条件分岐、{ref}`planar-arm` の座標を使います。基本では画像の横・縦の位置、発展では投影と座標変換を扱います。

## 必要な部品・工具

PCまたはスマートフォンのカメラ、固定具、色付き目印またはQRコード、照明、定規を使います。画像処理ライブラリとブラウザアプリは未実装です。まず保存画像の観察と画素座標の確認から始めます。

## 学ぶこと

### 画素と画像座標

画像は画素の集まりで、各画素に色や明るさがあります。画像の位置は通常、左上を基準に右・下へ増える座標で表します。これは車体の前・左・上の座標と違います。画像座標 $(p_x,p_y)$ の単位は画素であり、実空間のmではありません。

### 検出と判定

色検出は、画素の色が条件に入るかを調べ、まとまった領域を見つける方法から始めます。背景や影、照明が変わると色の値も変わります。QRコード等は印の情報を読めますが、ぼけや小ささ、隠れ方で失敗します。

「何かを検出した」「目的物を正しく検出した」「動作してよい」は別の判断です。対象がないとき、似た物があるとき、結果が古いときの動作も定めます。最初は検出を表示するだけにし、実機操作は確認後に加えます。

### カメラの校正と実空間

画像上の大きさは距離や向きにも依存し、一枚の画像の座標をそのままアームの位置へ使えません。カメラ内部の投影の特徴と歪みを校正し、カメラと作業平面の関係を求める必要があります。[OpenCV公式のカメラ校正資料](https://docs.opencv.org/4.x/dc/dbb/tutorial_py_calibration.html)。

作業対象が既知の平面上にある等の条件では、対応点から平面の座標へ変換できます。平面から外れた物体には同じ変換をそのまま使えません。距離センサ等との併用は追加課題です。

## 予想

照明、背景、距離、目印の角度を変えたとき、どの条件で検出しにくくなるでしょうか。

## 工作・配線・プログラミング

1. 撮影範囲を決め、カメラを固定して解像度と座標の向きを確認します。
2. 対象がある画像とない画像を準備し、検出結果を重ねて表示する処理を考えます。
3. 取得時刻、検出位置、有効性を記録します。
4. 対象の有無と処理遅れに応じた停止・表示の条件を作ります。
5. 実機を動かす場合は {ref}`practice-readiness` に従い、低い指令から確認します。

## 実験と計測

条件ごとに試行数、正しい検出、見逃し、別物の誤検出、撮影から判断までの時間を記録します。フレームが更新されない場合も別に記録します。正解は目視等で独立に確認します。

## 結果の整理と考察

成功率は、何を一試行としたかと分母を明記します。対象がある画像だけの評価では、対象がないときの誤検出を評価できません。遅い検出は正しくても、走行中には現在位置とずれる可能性があります。

## 課題

- **入門**：画像上で対象の位置を指し、右・下の座標を説明する。
- **基本**：条件を一つずつ変え、検出と失敗の表を作る。
- **発展**：既知平面の対応点を使って座標変換し、未使用の確認点で誤差を測る。

**確認問題**：画像の横方向へ10画素動いたら、実物も常に同じ距離動いていますか。**考え方**：距離や投影によって対応が変わります。校正と幾何条件が必要です。

## トラブル対処

| 症状 | 確認と対処 |
| --- | --- |
| カメラが使えない | 接続、利用権限、対応する実行環境を確認 |
| 別の物を拾う | 背景、色条件、領域の形・大きさを確認 |
| 位置が大きくずれる | 解像度、反転表示、歪み、座標変換、時刻を確認 |
